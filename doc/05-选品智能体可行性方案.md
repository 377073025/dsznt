# 选品智能体 —— 可行性方案

> 版本：v0.1　｜　日期：2026-10-24　｜　状态：草稿
> 前置文档：[04-选品智能体与可行性复评.md](04-选品智能体与可行性复评.md)（选品规则初版见其 3.4、3.5 节）
> 定位：**选品是闭环的关键步骤，由智能体完成，进入 MVP。** 现成工具只当数据来源和执行工具，不替代决策。

---

## 1. 结论先行

**可行。** 选品智能体要做的事拆开后，每一步都有成熟的技术手段；**难点不在 AI 判断，而在稳定拿到数据**。

| 选品要做的事 | 谁来做 | 可行性 | 关键依赖 |
|--------------|--------|--------|----------|
| 找需求：拼多多上什么好卖、在涨 | 程序采集 + LLM 归纳 | ✅ | 拼多多后台关键词分析（免费）+ 市场数据工具（建议订阅一款） |
| 找货源：1688 上谁有这个货 | 程序（以图搜货 + 关键词搜） | ✅ | 1688 网页读取层，或 1688 开放平台拍立淘接口 |
| 判断是不是同一个货 | LLM 看图 | ✅ | 多模态模型，成本很低 |
| 算利润 | 程序 | ✅ | 运费、费率参数 |
| 硬性过滤（代发、发货率、资质、侵权） | 程序 + LLM 看图 | ✅（侵权判断 ⚠️） | 规则库 |
| 打分排序 | 程序 | ✅ | 规则权重 |
| 写推荐理由、汇总 | LLM | ✅ | — |
| 测款判断、自动调权重 | 程序 + LLM 解读 | ✅ | 店铺数据（闭环已有） |
| **选得准不准** | 需要验证 | ⚠️ **未知** | 只能靠 POC 实测，见第 7 节 |

**最大的三个不确定性**：
1. 1688、拼多多网页读取能否稳定运行而不被风控拦截（每周几百次页面访问）
2. 拼多多需求端数据的精度（前台销量是累计值、第三方工具是估算值）
3. 智能体的选品命中率能否达到或超过人工

前两个靠 **第 1 周的技术 POC** 验证，第三个靠 **4–6 周的测款对比** 验证。

## 2. 选品的工作方式（人怎么选 → 智能体怎么选）

有经验的一件代发卖家选品一般是：
**看拼多多什么在卖 → 截竞品主图去 1688 以图搜同款 → 比价算利润 → 看供应商靠不靠谱 → 挑几款上架测。**

智能体完全复刻这个流程，只是把「看」和「比」交给程序和模型，并且每周能处理几百个候选，而人一般只能看几十个。

```
                 ┌──────────────────────────── 需求侦察 ────────────────────────────┐
  种子来源        │  ① 店内好卖款（延伸）  ② 拼多多热搜词/飙升词  ③ 类目热销榜/竞品  │
                 └──────────────────────────────┬───────────────────────────────────┘
                                                ↓  需求清单（约 50–100 个：关键词 + 竞品主图 + 竞品售价/销量）
                 ┌──────────────────────────── 货源匹配 ────────────────────────────┐
                 │  竞品主图 → 1688 以图搜货（Top 10）  +  关键词搜索（Top 10）        │
                 └──────────────────────────────┬───────────────────────────────────┘
                                                ↓  货源候选（约 500–1000 个 offer）
                 ┌──────────────────────────── 硬性过滤（程序）──────────────────────┐
                 │  一件代发 / 发货率 / 起批 / 库存 / 经营年限 / 类目黑名单            │
                 └──────────────────────────────┬───────────────────────────────────┘
                                                ↓  约 100–200 个
                 ┌──────────────────────────── 同款与合规审查（LLM 看图）─────────────┐
                 │  是否同款（Haiku）→ 是否侵权/需资质/图文不符（Sonnet）              │
                 └──────────────────────────────┬───────────────────────────────────┘
                                                ↓  约 30–60 个
                 ┌──────────────────────────── 利润核算 + 打分（程序）────────────────┐
                 │  按利润公式定价 → 7 维度打分 → 同一需求只保留最优货源             │
                 └──────────────────────────────┬───────────────────────────────────┘
                                                ↓  Top 5–10
                 ┌──────────────────────────── 推荐与汇总（LLM）─────────────────────┐
                 │  写「建议上新……，因为……」→ CEO 汇总 → 飞书卡片 → 店主拍板        │
                 └──────────────────────────────┬───────────────────────────────────┘
                                                ↓
                        铺货工具上架 → 14 天测款 → 留/改/汰 → 结果回流，调权重
```

## 3. 数据获取方案（选品专用）

### 3.1 需求端（拼多多）

| 数据 | 来源 | 获取方式 | 可靠性 | 建议 |
|------|------|----------|--------|------|
| 店内好卖款、回头客比例 | 本系统 | 已有 | 高 | 延伸选品的主要种子 |
| 搜索热词、飙升词、竞争度 | 拼多多后台「数据中心 → 关键词分析」 | 网页读取层（导出或读文本） | 高（官方数据） | **必用**，免费 |
| 类目热销榜、竞品近 30 天销量与价格 | 多多情报通 / 电霸 | 网页读取层读其页面或导出 | 中（第三方估算） | **建议订阅一款**，替代自己抓拼多多前台 |
| 竞品主图、售价、累计销量 | 拼多多前台搜索结果 | 网页读取层（手机网页版需登录） | 中（销量是累计值，如「已拼 1.2 万件」） | 第三方工具没有时的备用；**风控最严，访问量要小** |

> **为什么建议订阅一款市场数据工具**：拼多多前台是反爬最严的地方，自己抓风险最高、维护最累；买现成数据每月几百元，换来稳定性和低风险，是划算的。

### 3.2 供给端（1688）

| 数据 | 获取方式 | 说明 |
|------|----------|------|
| 以图搜货结果 | ① 1688 开放平台「拍立淘」图片搜索接口（有资质时）② 网页读取层：在 1688 网页上传图片搜索 | 选品最核心的动作 |
| 关键词搜索结果 | 同上（`alibaba.product.search` 或网页） | 补充以图搜货搜不到的情况 |
| 商品详情：代发价、SKU、起批量、库存、运费模板、销量、是否支持一件代发 | 商品详情页 / 详情接口 | 硬性过滤和利润计算的输入 |
| 供应商：经营年限、回头率、揽收/发货率、品质退货率、诚信通等级 | 商品页/店铺页上的服务指标 | 字段名称和是否展示需 POC 实测确认 |
| 是否支持代发助手直接下单 | 1688 分销工作台 / 所用铺货代发工具里的货源标记 | 计入「代发自动化」评分 |

### 3.3 网页读取层的做法（沿用 04 号文档的方案）

- **AI 认路，读网页文本取数**：数字从页面文本中提取，100% 准确；不靠截图识数。
- **固定脚本跑日常，页面改版时 AI 自动修路**，修好后更新脚本。
- **截图只用于看图**：竞品主图、货源主图的同款判断和合规审查。
- **限速**：1688、拼多多前台每天分批访问（例如每天 20–40 个页面），不集中爆发；遇到滑块或验证码立即暂停，飞书通知人工处理。
- **账号**：采集用的 1688 账号建议与采购付款账号分开，降低风控牵连。

## 4. 智能体分工

选品智能体内部拆成 5 个角色。**能用程序做的绝不用 LLM**，LLM 只做「看图」和「写字」两类事。

| 角色 | 实现 | 模型 | 输入 → 输出 |
|------|------|------|-------------|
| 需求侦察 | 程序采集 + LLM 归纳 | Sonnet 5.5 | 热词、榜单、店内数据 → 需求清单（去重、合并同义词、标注种子来源） |
| 货源匹配 | 程序 | 无 | 需求清单 → 1688 候选 offer 列表（结构化字段） |
| 同款审查 | LLM 看图 | Haiku 5.5 | 竞品主图 + 货源主图 → 是否同款、置信度 |
| 合规审查 | 规则 + LLM 看图 | Sonnet 5.5 | 货源图文 → 侵权风险、需资质类目、图文是否一致、违禁词 |
| 推荐撰写 | LLM | Sonnet 5.5 | 打分结果 → 每款一句「建议上新……，因为……」+ 风险提示 |

利润核算、硬性过滤、打分、排序全部是程序。CEO Agent（Opus 5.5）只负责把选品推荐和店铺运营建议合并成一份汇报。

## 5. 风险与对策

| # | 风险 | 可能性 | 影响 | 对策 |
|---|------|--------|------|------|
| R1 | 1688 / 拼多多网页触发风控、要求验证或限制账号 | 中 | 数据中断 | 限速分批；采集账号与经营账号分离；验证码转人工；优先用官方接口和第三方工具数据，网页读取作补充 |
| R2 | 拼多多需求数据不准（累计销量、第三方估算） | 高 | 误判需求 | 多源交叉：后台关键词热度（官方）+ 第三方销量 + 竞品数量；只用趋势和相对排序，不当绝对值用 |
| R3 | 同款误判（看起来像但材质/尺寸不同） | 中 | 售后、差评 | 同款置信度门槛；对比 SKU 规格与重量；高价款首单人工抽检 |
| R4 | 侵权、资质类目漏判 | 低–中 | 平台处罚 | 类目黑名单 + 品牌词库 + LLM 看图三层；首批默认排除高风险类目 |
| R5 | 选得「对」但大家都在卖，价格打穿 | 高 | 无利润 | 竞争度维度：竞品最低价 < 我方成本即淘汰；优先延伸选品（有店铺老客基础） |
| R6 | 供应商临时涨价、断货 | 中 | 订单无法履约 | 每款保留 1–2 个备选货源；在售款每日检查货源价格和库存（读取层） |
| R7 | 选品命中率不如人工 | 未知 | 项目价值 | POC 阶段与人工对照；规则权重按测款结果持续调优 |
| R8 | 平台对铺货数量的监管 | 中 | 店铺降权 | 每周推荐上限 5 款；同质化商品不重复上 |

## 6. 成本估算（单店，每周一次完整选品）

| 环节 | 数量 | 模型 | 估算 token | 费用 |
|------|------|------|-----------|------|
| 需求侦察归纳 | 1 次 | Sonnet 5.5 | 入 20k / 出 5k | ~$0.09 |
| 网页读取（文本） | 约 300 页 | 无 LLM（脚本） | — | ¥0 |
| 网页修路（偶发） | 0–2 次 | Sonnet 5.5 | 每次入 50k / 出 5k | ~$0–0.3 |
| 同款审查 | 约 200 对图 | Haiku 5.5 | 每对入 3.5k / 出 0.2k | ~$0.09 |
| 合规审查 | 约 60 个 | Sonnet 5.5 | 每个入 5k / 出 0.8k | ~$1.1 |
| 推荐撰写 | 10 个 | Sonnet 5.5 | 入 15k / 出 4k | ~$0.07 |
| CEO 汇总（并入日报） | — | Opus 5.5 | 已计入日报 | — |
| **合计** | | | | **≈ $1.5 / 周 ≈ ¥10 / 周** |

另需：市场数据工具订阅（需询价，参考价每月几百元）、铺货代发工具（需询价）。**LLM 成本不是问题，工具订阅才是主要成本。**

## 7. 验证计划（POC）

### 阶段 A：技术 POC（第 1 周）—— 数据能不能稳定拿到

| # | 验证项 | 成功标准 |
|---|--------|----------|
| A1 | 拼多多后台关键词分析：读取/导出热词与竞争度 | 连续 5 天自动获取成功 |
| A2 | 市场数据工具（试用版）：读取类目榜单、竞品销量价格 | 能拿到所选类目 Top 100 |
| A3 | 1688 以图搜货（网页）：用 20 张竞品主图搜同款 | ≥ 15 张能搜到同款货源；全过程无验证码，或验证码 ≤ 1 次 |
| A4 | 1688 详情页字段：代发价、一件代发、发货率、回头率、退货率等 | 字段可读，记录哪些字段拿不到 |
| A5 | LLM 同款判断：50 对人工标注的图片 | 准确率 ≥ 90% |
| A6 | 1688 开放平台：能否申请搜索/拍立淘接口 | 明确结果（能/不能） |

**通过条件**：A1、A3、A4、A5 通过 → 进入阶段 B。A3 风控严重 → 改为「以 1688 开放平台接口或铺货工具货源池为主」，重新评估。

### 阶段 B：离线回测（第 2 周）—— 智能体选的货靠不靠谱

- 用你过去上过的款（含卖得好和卖不好的）做测试集，让智能体在「当时」的数据下打分
- 看智能体的高分款是否与实际卖得好的款一致
- 同时让你从同一批候选中人工挑 5 款，与智能体 Top 5 对比重合度和理由

**通过条件**：智能体 Top 5 中至少 2–3 款与你的判断一致，且你认可推荐理由。

### 阶段 C：线上测款对照（第 3–8 周）

- 每周：智能体推荐 5 款 + 你人工选 2–3 款，全部上架测款 14 天
- 指标：测款成功率（达到「留款」标准的比例）、首月毛利、退货率
- 每两周按测款结果调一次权重

**通过条件**：智能体测款成功率 ≥ 人工选品，或差距在可接受范围内但节省了大量人工时间。

### 时间与人工投入

| 阶段 | 时长 | 你需要做的 |
|------|------|-----------|
| A | 1 周 | 提供 20 张竞品图、标注 50 对同款图、试用一款市场数据工具、扫码登录 |
| B | 1 周 | 提供历史上新记录，人工挑 5 款对照 |
| C | 6 周 | 每周拍板、铺货、人工选 2–3 款对照 |

## 8. MVP 范围调整

选品智能体从原计划的 V0.2 **提前到 MVP**，MVP 的范围变为：

| 模块 | MVP 内容 |
|------|----------|
| 数据接入 | 双通道（API + 人工导入）+ 网页读取层（拼多多后台、1688） |
| 选品智能体 | 延伸选品 + 机会选品（补位选品放 V0.2）；硬性过滤、同款与合规审查、利润打分、推荐；测款跟踪 |
| 运营闭环 | 看数、建议、CEO 汇总、飞书拍板、文案/修图物料、验收、回流 |
| 上架 | 铺货工具 + 系统生成的标题主图 |
| 履约 | 第三方代发工具（不开发） |

**建议开发顺序**：网页读取层 → 选品智能体 → 测款跟踪 → 运营闭环。原因：选品是最先产生价值的环节，也最依赖数据层，先把数据层和选品跑通，再补运营闭环。

---

## 9. 需要你决定的事

1. **是否订阅一款拼多多市场数据工具**（多多情报通或电霸），作为需求端主数据源。不订阅则改为读拼多多前台，风控风险更高。
2. **选择一款铺货代发工具**，用于上架和自动下单，其货源标记用于「代发自动化」评分。
3. **首批类目**：选 1–2 个你熟悉、无需资质的类目开始（类目越聚焦，数据越准、规则越好调）。
4. **是否接受网页读取的风控风险**，以及是否准备一个单独的 1688 采集账号。
