## 1. 项目基准：人工尽量少

**原则**：能自动的全部自动；只在以下三种情况保留人工：

| 类型 | 说明 | 例子 |
|------|------|------|
| **决策闸门**（故意保留） | 对钱、对店铺有实际影响的决定 | 拍板建议、确认上新、确认采购付款 |
| **平台限制**（没办法绕过） | 平台要求真人操作或资质 | 店铺主账号授权、扫码登录、验证码、开放平台资质申请 |
| **兜底通道**（自动失败时才用） | 自动通道失败时的备用方案 | API 拿不到数据时手动导入 |

每个环节都按「**自动优先 → 半自动 → 人工兜底**」三级设计，系统自动判断走哪一级，并在飞书里告诉店主当前是哪一级。

## 2. 数据接入：双通道设计（API + 人工导入）

### 2.1 通道总览

```
                   ┌─────────── 自动通道 ───────────┐
拼多多开放平台 API ──┤ 商品、订单、物流（需应用资质）   │
后台采集器（脚本） ──┤ 访客、加购、推广数据（API 没有的）├──┐
1688 API / 采集器 ──┤ 货源价格、库存、代发标签          │  │
                   └────────────────────────────────┘  ├─→ 标准化 → 校验 → 指标库
                   ┌─────────── 人工兜底 ───────────┐  │
后台导出 Excel ─────┤ 拖进 Web / 发到飞书机器人        ├──┘
                   └────────────────────────────────┘
```

### 2.2 数据项 × 通道矩阵

| 数据 | 通道 1：开放 API | 通道 2：后台采集器 | 通道 3：人工导入 | 实际主通道 |
|------|------------------|--------------------|------------------|------------|
| 商品（标题、主图、价格、SKU） | ✅ 有资质时 | ✅ | ✅ | API > 采集器 |
| 订单 | ✅ 有资质时（敏感字段需多多云） | ✅ 只取统计值 | ✅ | API > 采集器 |
| **单款访客、加购、转化** | ❌ 未找到公开接口 | ✅ | ✅ | **采集器** |
| 推广数据 | 部分 | ✅ 报表下载 | ✅ | 采集器 |
| 1688 货源（价格、库存、代发标签） | ⚠️ 需 1688 开放平台资质 | ✅ | ✅ | 采集器 > API |
| 改动事件 | ❌ | ✅ 每日商品快照对比 | ✅ | 系统自记 + 快照对比 |

### 2.3 什么是「后台采集器」，风险多大

为了做到人工最少，**API 拿不到的访客、加购数据只能靠采集器**：在本地电脑上用一个独立的浏览器（Playwright），使用店主已登录的商家后台会话，每天定时打开「数据中心 → 商品数据」，**读取或点导出按钮下载 Excel**，然后交给导入程序。

| 设计要点 | 说明 |
|----------|------|
| 只读不写 | 采集器只能打开页面、下载报表，不做任何修改操作 |
| 低频 | 每天 2–5 次，模拟正常人工操作节奏，不并发、不翻几百页；设每日页数上限 |
| 登录由人完成 | 首次及会话过期时，系统在飞书提醒店主扫码登录（约每 1–4 周一次，取决于平台会话有效期） |
| 读文本、不靠截图读数 | 用固定脚本（录制好的步骤）**读网页文本取数**，不让 AI 看截图读数字：截图读数易错、token 成本高 10 倍以上，且截图并不降低风控风险（打开页面的动作一样） |
| 截图只在这些场景用 | 脚本失效时 AI 认路；同款、合规、上架核对的看图判断；页面用自定义字体打乱数字或用图表图片展示时识别数字；每次采集存一张截图作证据（不调用模型） |
| 自愈 | 页面改版导致脚本失败时，降级为飞书提醒「今天请手动导出」，同时把页面结构变化记录下来，由开发者修脚本 |

**风险**：拼多多有风控，自动化访问存在被要求验证、限制登录甚至处罚的可能；平台规则对「使用非官方工具操作后台」有约束。**这是用「人工最少」换来的风险，需要你知情并决定是否接受。** 降低风险的做法：只用导出功能、频率与人工一致、出现验证码立即停止并通知人。

**风险看什么**：每天 2–5 次本身风险很低，关键在「每次打开多少页」和「浏览器像不像真人」。

| 因素 | 风险判断 |
|------|----------|
| 读拼多多自家后台，每天 2–5 次、每次几十页以内 | 低，与店主自己看后台接近 |
| 按单品逐页拉数据（50 款 ≈ 50+ 页） | 中，优先改用导出报表 |
| 1688 每周批量以图搜货、看详情（几十到上百个候选） | **主要风险点**，用独立采集账号、分几天分批 |

**运行规范**（让访问更像真人）：

1. 用**有界面的真实 Chrome**，长期使用同一份浏览器配置（保留登录状态和缓存），不用无界面模式。
2. 固定在**同一台电脑、同一网络**运行，与平时人工登录环境一致。
3. 运行时间随机偏移，不整点准时开始；翻页之间随机停顿几秒。
4. 设每日页数上限；1688 选品分几天分批跑完。
5. 出现验证码或访问受限，**立即停止并通知人工**，不自动重试（熔断）。

### 2.4 自动通道失败时的降级规则

1. 采集器失败 → 重试 2 次 → 飞书通知「今天数据未自动获取，请扫码登录 / 手动导出」并附上一步一步的截图指引
2. 超过 24 小时未收到数据 → 早报中该店标「数据缺失」，**不出任何推测性建议**
3. 人工导入后，自动补跑当天分析

## 3. 选品智能体

### 3.1 定位

**在 1688 找「能在拼多多卖、能赚钱、能一件代发、最好能自动下单」的货，按评分排出候选清单，交 CEO 汇总后由店主拍板上新。**

它是闭环的另一个入口：原闭环由「店铺数据」触发建议，选品由「市场 + 货源数据」触发建议，最终都走「CEO 汇总 → 店主拍板 → 派活 → 验收 → 回流」。

```
拼多多市场数据 ─┐
店铺自身数据 ──┼─→ 选品智能体 ─→ 候选清单 ─→ CEO 汇总 ─→ 店主拍板 ─→ 铺货/上新 ─→ 测款 ─→ 回流
1688 货源数据 ─┘                                                        ↑
                                                         测款结果反哺选品规则 ┘
```

### 3.2 选品的三种触发方式

| 方式 | 触发 | 例子 |
|------|------|------|
| 延伸选品 | 店内某款持续好卖 | 柑橘香薰连续两周最好卖 → 在 1688 找同系列其他香型、同供应商的关联款 |
| 补位选品 | 某款衰退或供应商出问题 | 海盐款货源断货/涨价 → 在 1688 找同款替代货源（以图搜货） |
| 机会选品 | 每周定时扫描 | 拼多多类目热搜词、竞品热销款 → 在 1688 找对应货源 |

### 3.3 数据来源

| 数据 | 来源 | 获取方式 |
|------|------|----------|
| 1688 货源：价格、起批量、代发价、库存、销量、复购率、供应商等级、48h 发货率、品质退货率、是否支持一件代发、是否支持代发推单 | 1688 | 1688 开放平台 API（`alibaba.product.search`、详情、以图搜货，需资质）；无资质时用采集器读取搜索结果页和详情页 |
| 拼多多需求端：类目热搜词、竞品售价与销量 | 拼多多 | 商家后台「搜索词分析」等页面（采集器）；或拼多多前台搜索结果（采集器，只读） |
| 店铺自身：哪些款好卖、复购、退货原因 | 本系统数据库 | 已有 |
| 平台规则：禁售类目、需资质类目、违禁词 | 拼多多规则中心 | 人工整理成规则库，定期更新 |

### 3.4 选品规则（初版，可配置、会根据测款结果自动调参）

选品分 **硬性过滤 → 打分 → 人工拍板** 三步。**硬性过滤和打分都由程序完成，LLM 只做两件事：判断货源图片与描述是否一致、写推荐理由。**

#### 第一步：硬性过滤（任一不满足即淘汰）

| # | 规则 | 默认阈值 | 原因 |
|---|------|----------|------|
| H1 | 支持一件代发 | 必须 | 模式前提 |
| H2 | 预估毛利率 | ≥ 25% | 见 3.5 利润公式；低于此扣掉推广和售后基本不赚钱 |
| H3 | **预估单款净利**（扣除退货损失、推广费、扣点后） | **> 0**；单件毛利 ≥ ¥3 | 选品目标是「无货源、不亏」；同时防止低价款绝对值太小 |
| H4 | 供应商 48 小时发货率 | ≥ 95% | 拼多多对延迟发货处罚严格 |
| H5 | 品质退货率 / 纠纷率 | 低于类目均值 | 一件代发售后成本由店铺承担 |
| H6 | 非禁售、非需特殊资质类目 | 必须 | 食品、化妆品、医疗器械、3C 认证、儿童用品等需资质，初期全部排除 |
| H7 | 无品牌侵权风险 | 必须 | 标题/图片含知名品牌、IP 形象的排除（LLM 看图辅助判断） |
| H8 | 体积重量适中、非易碎 | 可配 | 运费和破损售后会吃掉利润 |
| H9 | 供应商经营年限 | ≥ 2 年 | 降低跑路、断货风险 |
| H10 | 库存充足 | ≥ 200 件 | 避免卖起来就断货 |
| H11 | 诚信通 / 实力商家 / 源头工厂 | 至少满足一项（可配） | 供应商诚信度 |
| H12 | 回头率 | ≥ 类目均值（可配） | 买家认可度 |
| H13 | 品质体验分 | ≥ 4.0（可配） | 货不对板、质量问题 |
| H14 | 纠纷率 | ≤ 类目均值（可配） | 售后风险 |

**两类合规风险分开管**：

| 风险类型 | 例子 | 靠什么拦 |
|----------|------|----------|
| 履约风险 | 发货慢、断货、货不对板 | 供应商维度：H4、H5、H9–H14；**在售款每天复查供应商指标**，变差则提醒换货源 |
| 商品风险 | 类目需资质、品牌或外观侵权、盗图、描述不符 | 商品维度：H6、H7 + 类目黑名单、品牌词库、看图审查；文案和图片不超出实物 |

供应商再靠谱也挡不住商品风险（很多 1688 商品本身就是仿款），两者必须同时生效。

#### 第二步：打分（满分 100）

| 维度 | 权重 | 计算方式 |
|------|------|----------|
| 利润空间 | 25 | 毛利率、单件毛利，按区间给分 |
| 市场需求 | 20 | 拼多多对应关键词热度、竞品近 30 天销量 |
| 竞争程度 | 10 | 同款在拼多多的卖家数、价格带是否已被打穿（竞品最低价 < 我方成本 → 0 分） |
| 供应商质量 | 15 | 供应商等级、复购率、发货率、退货率综合 |
| **代发自动化程度** | 15 | 支持「代发推单 / 代发助手直接下单 + 物流自动回传」得满分；只支持一件代发、需手动下单得一半 |
| 与店铺契合度 | 10 | 与店内好卖款同系列/同人群/同价格带（延伸选品加分） |
| 素材可用性 | 5 | 供应商是否提供高清原图、白底图、视频；图片是否可直接修图使用 |

总分 ≥ 70 进入候选清单；每周最多推荐 5 款（可配），**避免无脑铺货触发平台监管**。

#### 第三步：测款与淘汰（回流）

| 阶段 | 规则 |
|------|------|
| 测款期 | 上新后 14 天 |
| 留款 | 14 天内访客 ≥ 300 且转化率 ≥ 店铺均值 × 0.8 |
| 观察 | 访客够但转化低 → 交给电商 Agent 优化主图/价格，再观察 7 天 |
| 淘汰 | 14 天访客 < 100，或转化率 < 店铺均值 × 0.5 → 建议下架 |
| 亏损上限 | 测款期累计亏损（推广费 + 退货损失 − 毛利）达到每款上限（可配）→ 自动发起下架，写入确认后执行 |
| 规则自优化 | 每月统计「各维度得分」与「测款是否成功」的关系，自动微调权重，并把调整写进月报交店主确认 |

### 3.5 利润公式

```
预估毛利 = 拼多多售价
         − 1688 代发价（含 SKU 差价）
         − 运费（供应商代发运费，按首重/续重）
         − 平台技术服务费（按拼多多实际费率配置，默认 0.6%）
         − 预估售后损耗（售价 × 类目退货率 × 单次退货损失系数）
         − 预估推广费（售价 × 目标推广费率，默认 10%）
         − 代发工具费用分摊（如有）

拼多多售价 = 参考竞品价格带中位数，且 ≥ 成本 /（1 − 目标毛利率）
```

**选品口径：单款净利 > 0 即可（无货源、不亏）。** 拼多多代发不赚钱，往往不是差价算错，而是下面这些成本没算全，必须全部计入：

| 成本 | 说明 | 计入方式 |
|------|------|----------|
| 退货与退款 | 退回运费、供应商不收退货、退款不退货 | 售后损耗 = 售价 × 类目退货率 × 单次退货损失系数；**上线后用本店真实退货率替换估算值** |
| 推广费 | 不投流量很难起量；测款期基本在亏 | 目标推广费率；测款期另设**每款最大亏损额度** |
| 平台扣点与罚款 | 技术服务费；发货超时等罚款 | 扣点按费率；罚款靠供应商筛选规避，出现后计入该款实际成本 |
| 保证金占用 | 开店及部分类目需缴纳 | 不分摊到单件，作为资金占用单独记账 |

所有参数在设置页可调；售价由程序计算，不由 LLM 决定。

### 3.6 「代发助手可以直接下单」的处理

1688 和第三方工具有几种自动化程度不同的代发方式，选品智能体要把它识别出来并计入评分：

| 方式 | 自动化程度 | 说明 |
|------|------------|------|
| 第三方代发工具（如风火递、代发助手王、店管家等） | 高：铺货、自动抓单、自动下单、免密支付、物流回传 | 需在拼多多服务市场订购授权，部分收费；本系统不重复造轮子，**与它们配合** |
| 1688 官方「代发推单」 | 中：需在旺旺触发推单卡片，批量付款，物流自动回传 | 官方资料目前只明确提到淘宝和抖店，**拼多多是否支持需实测** |
| 普通一件代发 | 低：手动在 1688 拍单、填地址、回填单号 | 只作兜底 |

**建议**：订单履约（抓单→下单→付款→回传单号）直接交给成熟的第三方代发工具，本系统专注「选品决策 + 运营闭环」。这样选品智能体只要判断「这个货源能不能被你用的代发工具自动下单」，在候选卡片上标出来即可。

### 3.7 选品输出（飞书卡片）

```
┌ 本周选品推荐（3 款） ─────────────────────────────┐
│ ① 葡萄柚香薰蜡烛 200g              总分 84          │
│   1688 代发价 ¥11.8  建议售价 ¥29.9  预估毛利 ¥8.6（29%）│
│   供应商：xx 工厂（5 年，48h 发货率 98%，复购率 32%）  │
│   代发：✅ 支持代发助手自动下单 + 物流回传            │
│   理由：柑橘款连续两周全店第一，同供应商同系列，     │
│         拼多多「香薰蜡烛 葡萄柚」近 30 天竞品销量上升  │
│   [同意上新] [不要] [改一改]                         │
└──────────────────────────────────────────────────┘
```

店主点「同意上新」后：CEO 派活 → 图片 Agent 修图、文案 Agent 写标题 → 铺货（见第 4 节）→ 进入 14 天测款。

### 3.8 市场上现成的选品工具（能否直接用）

#### 工具分类

| 类别 | 代表工具 | 能提供什么 | 支持拼多多 | 对接方式 | 价格 |
|------|----------|------------|------------|----------|------|
| 拼多多官方 | 商家后台「数据中心」（关键词分析、大盘、商品数据） | 搜索词热度、竞争度、类目大盘、本店商品数据 | ✅ | 后台查看/导出 | 免费 |
| 拼多多市场数据（第三方） | **多多情报通**（原多多参谋）、**电霸** | 类目热销榜、竞品销量与价格监控、关键词趋势、选款 | ✅（专做拼多多） | 网页 SaaS，未发现公开 API，可导出 | 需询价；电霸 2022 年资料为单类目 ¥399/月、¥1599/年，全类目 ¥6999/年 |
| 1688 官方分销 | **1688 分销工作台**（fenxiao.1688.com，含 AI 选品、关联多货源、自动匹配下游类目） | 代发货源池、选品推荐、铺货、免手动下单 | 需实测（官方资料多提淘宝、抖店） | 网页/客户端 | 部分免费，需绑定下游店铺 |
| 铺货 + 代发履约（第三方） | **麦爆了**、**店管家**、**风火递**、**代发助手王**、**妙手** | 1688 一键铺货、订单自动推送到 1688、自动采购、物流单号回传、库存同步，部分带 AI 选品 | ✅（多数明确支持） | 拼多多服务市场订购授权 | 需询价，多有免费试用 |
| AI 选品 Agent（第三方） | 若干 RPA/Agent 厂商 | 自动抓取榜单、生成选品报告 | 部分 | 定制 | 偏贵，宣传数据难核实 |

#### 判断

1. **没有一个工具能完整替代选品智能体**：市场数据工具只看「拼多多需求端」，铺货/代发工具只看「1688 供给端 + 履约」，都不会按你的利润公式、代发自动化程度、店铺契合度做综合打分，也不会接入你的「CEO 汇总 → 拍板 → 测款 → 回流」闭环。
2. **但它们能省掉最难的两块开发**：
   - 拼多多市场数据：用多多情报通/电霸代替自建拼多多前台采集，**更稳定、合规风险更低**。
   - 1688 货源与履约：用分销工作台或铺货代发工具代替自建 1688 采集和下单，**它们本身就是平台授权的应用**。
3. **都没有公开 API**：只能通过「导出文件」或第 2 节的网页读取层接入，属于数据源，不是可编程接口。

#### 建议架构：工具做「眼睛和手」，选品智能体做「大脑」

```
多多情报通 / 电霸（需求端：热搜词、竞品销量价格）──┐
拼多多后台数据中心（关键词分析、本店数据）────────┤
1688 分销工作台 / 铺货工具（货源池、代发标签）────┼─→ 选品智能体（过滤 + 打分 + 理由）
本系统数据库（好卖款、测款结果）─────────────────┘           │
                                                            ↓
                                     CEO 汇总 → 飞书拍板 → 铺货工具一键铺货 + 自动代发
```

#### 分阶段（已更新：选品智能体进入 MVP，详见 [05 号文档](05-选品智能体可行性方案.md)）

| 阶段 | 做法 | 人工 |
|------|------|------|
| MVP | 选品智能体：从上述工具和网页读取层获取数据，自动过滤打分，飞书推荐，拍板后在铺货工具中铺货 | 每周点确认 + 铺货 |
| V0.2 | 补位选品、以图搜替代货源；测款数据积累后自动调权重 | 只点确认 + 铺货 |
| V0.3 | 铺货工具若开放接口或拿到开放平台资质则全自动 | 只点确认 |

#### 选型前需要试用确认的点

| 工具 | 确认什么 |
|------|----------|
| 多多情报通 / 电霸 | 当前价格；你的类目数据是否充足；能否导出竞品销量、价格、关键词趋势 |
| 1688 分销工作台 | 是否支持绑定拼多多店铺；AI 选品的依据和可导出性 |
| 麦爆了 / 店管家 / 风火递 / 代发助手王 | 拼多多铺货是否稳定；自动下单 + 免密支付 + 物流回传是否全自动；能否导出货源字段（代发价、发货率、退货率）；收费 |

## 4. 上架：怎样做到人工最少

| 级别 | 方式 | 人工 | 前提 |
|------|------|------|------|
| 自动 | 拼多多开放平台 `pdd.goods.add` 直接发布 | 只需「写入确认」点一下 | 需应用资质（小商家大概率没有） |
| 半自动 | 用第三方铺货/代发工具从 1688 一键铺货到拼多多，系统生成的标题和主图同步覆盖 | 在工具里点铺货 + 点确认 | 订购铺货工具 |

**建议**：MVP 用「第三方铺货工具 + 系统生成的标题/主图」，每款人工约 1–2 分钟；拿到开放平台资质后切自动。

## 6. 整体可行性复评

### 6.1 各智能体

| 智能体 | 能否完成要求 | 依赖 | 主要风险 |
|--------|--------------|------|----------|
| 数据接入（程序） | ✅ 双通道可实现 | 采集器、开放平台资质（可选） | **采集器的平台风控风险**；页面改版需维护 |
| 电商 Agent（看数/建议） | ✅ | 数据接入 | 小样本误判 → 样本门槛 + 按周看 |
| **选品 Agent** | ✅ 规则化选品可行 | 1688 与拼多多市场数据 | 1688 反爬较严、开放平台需资质；需求端数据只能近似（热搜、竞品销量） |
| CEO Agent | ✅ | 无 | 无明显风险 |
| 文案 Agent | ✅ | 违禁词库 | 规则库维护 |
| 图片 Agent | ✅（修图为主） | 生图服务 | 生成图与实物不符 → 只做修图、换背景、场景合成，不生成商品本体 |
| 上架 | ⚠️ 半自动 | 铺货工具或开放平台资质 | 无资质时需人点一次 |
| 验收 Agent | ✅ | 采集器读店铺状态 | 读不到时由人确认 |
| 订单履约 | ✅ 交给第三方代发工具 | 代发工具订购 | 不在本系统范围 |

### 6.2 结论

**可行。** 按「自动优先 + 人工兜底」设计，日常人工可以压到每天 5 分钟左右。真正的不确定性只有三个，都不是 AI 能力问题：

1. **后台采集器的风控风险**（需要你决定是否接受）
2. **1688 和拼多多开放平台资质能否申请到**（决定是否还需要采集器）
3. **代发工具对拼多多 + 你选的 1688 供应商的支持情况**（决定选品里「自动下单」能覆盖多少货源）

### 6.3 Token 与成本复评

| 部分 | 估算 | 说明 |
|------|------|------|
| 原闭环（单店，优化后） | ¥1–2 / 天 | 见 03 号报告 4.3 节 |
| 选品 Agent | ¥5–10 / 周 | 程序先过滤出约 50 个候选，LLM 只对这些看图、写理由：Haiku 5.5 初筛 + Sonnet 5.5 精评，Opus 5.5 不参与 |
| 采集器 | ≈ ¥0 | 固定脚本，**不使用 LLM 操作浏览器** |
| 采集器若改用 AI 看截图操作 | ¥5–15 / 天 | 每次几十张截图，**不建议**，只在脚本失效时临时兜底 |
| 生图 | ¥0.1–0.5 / 张 | 取决于服务商 |
| 第三方代发/铺货工具 | 按工具定价 | 非 token 成本，需单独询价 |

**合计**：单店 AI 成本约 **¥50–100/月**，不会花费大量 token。成本的大头会是代发工具订阅和生图，不是 LLM。
