## 1. 总结论

**项目可行，建议进入 POC。**

| 维度 | 结论 |
|------|------|
| AI 能力 | ✅ 不是瓶颈。看数、诊断、建议、汇总、选品判断、文案、看图验收都在现有模型能力范围内 |
| 数据获取 | ⚠️ **最大风险**。拼多多对小商家几乎不开放流量数据接口，1688/拼多多网页有风控；靠「API + 网页读取 + 人工导入」三通道兜住 |
| 自动执行 | ⚠️ 上架、下单依赖第三方铺货代发工具或开放平台资质；可做到「半自动、人点一下」 |
| 人工投入 | ✅ 日常可压到 **每天约 5 分钟**（飞书里点按钮），另每 1–4 周扫码登录一次 |
| Token 成本 | ✅ **不会花大量 token**：单店 LLM 费用约 **¥70–130/月**（含选品）；加生图后 AI 相关合计约 ¥100–280/月 |
| 总成本 | 主要成本是工具订阅（市场数据、铺货代发）和生图，不是 LLM |
| 未验证项 | 网页读取的风控稳定性、1688 详情字段可得率、AI 同款判断准确率、**选品命中率** |

## 2. 项目基准与已确认决定

**基准：人工尽量少。** 人工只保留在三种情况：决策闸门（拍板、确认上新、确认付款）、平台硬性要求（授权、扫码登录、验证码）、自动失败时的兜底。

| 决定 | 结论 |
|------|------|
| 平台 | 拼多多 |
| 模式 | 一件代发，货源 1688 |
| 交互渠道 | 飞书（主入口），Web 控制台为辅 |
| 出图 | AI 生成 + 素材库，两者都要（以修图、换背景、场景合成为主） |
| 部署 | 先本地部署 |
| 多用户 | 需要（店主 / 运营分权限） |
| 数据获取 | API 与人工导入两种都做；没有 API 的用网页读取 |
| 选品 | **关键步骤，由智能体完成，进入 MVP** |

## 4. 各智能体可行性

| 智能体 / 模块 | 职责 | 能否完成 | 主要依赖 | 主要风险与对策 |
|---------------|------|----------|----------|----------------|
| 数据层 | 三通道获取并校验数据 | ✅ | 网页读取层、API 资质（可选） | 风控 → 限速、只读、验证码转人工、自动降级到人工导入 |
| **选品智能体** | 需求侦察、货源匹配、同款与合规审查、利润打分、推荐、测款跟踪 | ✅ 流程可实现，⚠️ 命中率待验证 | 拼多多关键词/市场数据、1688 以图搜货与详情 | 需求数据是估算 → 只看趋势与相对排序；同款误判 → 置信度门槛 + 规格比对 |
| 电商运营 Agent | 漏斗、分款、异常、归因、建议 | ✅ | 访客/加购数据（网页读取） | 小样本误判 → 样本门槛、按周对比；归因依赖改动记录 → 系统自记 + 每日商品快照 |
| CEO Agent | 汇总、派活、验收 | ✅ | — | 无明显风险 |
| 文案 Agent | 标题、卖点、详情 | ✅ | 违禁词库 | 规则库需维护 |
| 图片 Agent | 修图、换背景、场景图、素材挑选 | ✅ | 外部生图服务 | 凭空生成商品本体易被判描述不符 → 不做 |
| 上架 | 铺货、改图改价 | ⚠️ 半自动 | 铺货工具或开放平台资质 | 无资质时需人在工具里点一次 |
| 验收 | 检查物料与店铺实际状态 | ✅ | 网页读取层读店铺状态 | 读取失败时人工确认 |
| 订单履约 | 抓单、下单、付款、回传 | ✅（不自研） | 第三方代发工具 | 交给成熟工具 |
| 飞书交互 | 推送卡片、按钮拍板、对话修改 | ✅ 待 POC | 飞书长连接 | 卡片回调若不走长连接 → 内网穿透兜底 |

## 5. 数据获取方案（最终）

### 5.1 三通道，自动降级

| 优先级 | 通道 | 用于 |
|--------|------|------|
| 1 | 开放平台 API | 有资质时：拼多多商品/订单、1688 搜索/拍立淘/详情 |
| 2 | 网页读取层 | API 拿不到的：拼多多后台访客/加购/关键词、1688 搜索与详情、市场数据工具页面 |
| 3 | 人工导入 | 前两者失败时；系统在飞书通知并给出操作指引 |

### 5.2 网页读取层的做法

在本地独立浏览器中使用已登录会话访问网页：

| 层级 | 做法 | 场景 | 成本 |
|------|------|------|------|
| 固定脚本 | AI 首次摸清路线后录成脚本，每天按脚本跑，**直接读网页文本取数** | 日常 | ≈ ¥0 |
| AI 认路 | 页面改版、脚本失败时，AI 读页面结构重新找路，修好后更新脚本 | 偶发自愈 | 每次约 ¥0.5–2 |
| AI 看截图 | 只用于看图：同款判断、合规审查、上架后核对 | 少量 | 按张计 |

**不采用「全程截图让 AI 读数」**：数字可能读错、成本高几十倍（单店约 ¥250/月）、速度慢。

### 5.3 平台接口现状

| 平台 | 情况 |
|------|------|
| 拼多多开放平台 | 商家自研系统面向「有软件开发能力的大型商家」，小商家大概率申请不到；订单敏感数据需多多云；**单款访客/加购未找到公开接口** |
| 1688 开放平台 | 有搜索、详情、拍立淘图片搜索接口，需企业开发者资质和权限审核；分销铺货、自动下单多属于服务商合作范畴 |

## 6. 选品可行性（关键步骤）

**流程**：店内好卖款 / 拼多多热词 / 类目榜单 → 竞品主图 → 1688 以图搜货 + 关键词搜 → 硬性过滤 → AI 同款与合规审查 → 利润计算与 7 维度打分 → 推荐理由 → CEO 汇总 → 飞书拍板 → 铺货 → 14 天测款 → 留/改/汰 → 调权重。

| 判断点 | 结论 |
|--------|------|
| 技术上能否实现 | ✅ 每一步都有成熟手段 |
| 数据是否够用 | ⚠️ 需求端：拼多多后台关键词（官方、免费）+ 建议订阅一款市场数据工具（多多情报通 / 电霸）；供给端：1688 网页或接口 |
| 现成工具能否替代 | ❌ 市场数据工具只看需求端，铺货代发工具只看货源与履约，都不做综合打分，也没有公开 API；**作为数据源和执行工具使用** |
| 代发自动下单 | ✅ 由第三方代发工具完成；选品时识别「能否被代发工具自动下单」并计入评分 |
| 选得准不准 | ⚠️ 未知，只能通过离线回测和线上测款对照验证 |

选品规则（硬性过滤 10 条、打分 7 维度、利润公式、测款淘汰规则）见 [04 号文档 3.4–3.5 节](04-选品智能体与可行性复评.md)。

## 7. 人工参与（最终）

| 动作 | 频率 | 性质 |
|------|------|------|
| 拍板运营建议 | 每天 1–3 次 | 决策闸门 |
| 确认上新（选品推荐） | 每周 ≤ 5 次 | 决策闸门 |
| 写入确认（改图、改价、下架） | 按需 | 决策闸门 |
| 在铺货工具点铺货 | 每款一次（无开放平台资质时） | 平台限制 |
| 扫码登录拼多多后台、1688 | 约每 1–4 周 | 平台限制 |
| 处理验证码 | 偶发 | 平台限制 |
| 手动导出数据 | 仅在自动失败时 | 兜底 |
| 首次配置、年度授权续期 | 一次 / 每年 | 平台限制 |

**日常人工：约 5 分钟/天**，基本都在飞书里完成。

## 8. 成本（单店 / 月）

| 项目 | 估算 | 说明 |
|------|------|------|
| 运营闭环 AI 费用 | ¥30–60 | 看数、建议、汇总、派活、验收、复盘；已含缓存、Batch、模型分级优化 |
| 选品 AI 费用 | ¥40–50 | 每周一次完整选品约 ¥10 |
| 网页读取 | ¥0–20 | 固定脚本不耗 token；只有修路时花费 |
| 生图 | ¥30–150 | 按每天约 10 张、每张 ¥0.1–0.5 |
| **AI 相关合计** | **约 ¥100–280** | |
| 市场数据工具 | 需询价 | 参考：电霸 2022 年单类目 ¥1599/年 |
| 铺货代发工具 | 需询价 | 多有免费试用 |

模型分工：CEO 汇总与验收用 Claude Opus 5.5（$4 / $20 每百万 token），分析、选品审查、文案用 Sonnet 5.5（$2 / $10），同款初筛等简单活用 Haiku 5.5（$0.10 / $0.50）。

**会让 token 失控的做法（全部规避）**：把原始报表整张塞给 LLM；让 Agent 无上限循环调工具；用全能编程 Agent 框架跑日常任务；全程截图让 AI 读数。

## 9. 风险清单（按严重程度）

| # | 风险 | 可能性 | 影响 | 对策 |
|---|------|--------|------|------|
| 1 | 网页读取触发拼多多 / 1688 风控 | 中 | 数据中断、账号受限 | 只读、限速分批、采集账号分离、验证码转人工、出现「访问受限」立即停止 |
| 2 | 选品命中率不如人工 | 未知 | 项目核心价值 | POC 回测 + 6 周测款对照；按结果调权重 |
| 3 | 需求端数据精度不足 | 高 | 选品误判 | 多源交叉，只用趋势和排序 |
| 4 | 价格战，选对了也不赚钱 | 高 | 无利润 | 竞品最低价低于我方成本即淘汰；优先延伸选品 |
| 5 | 小样本导致运营诊断误判 | 高 | 错误建议 | 样本门槛，按周对比，建议须人拍板 |
| 6 | 同款误判、侵权或资质漏判 | 中 | 售后、处罚 | 置信度门槛、规格比对、类目黑名单 + 品牌词库 + 看图 |
| 7 | 供应商涨价断货 | 中 | 履约失败 | 每款 1–2 个备选货源，在售款每日检查 |
| 8 | 第三方工具对拼多多支持不完整 | 中 | 半自动程度下降 | 试用 1–2 款后再定 |
| 9 | 飞书卡片回调在本地部署下不可用 | 低 | 交互受限 | 内网穿透兜底 |
| 10 | 平台规则变化、页面改版 | 中 | 维护成本 | AI 自愈修路 + 失败降级人工 |

## 11. 尚需你决定的事

| # | 事项 | 影响 |
|---|------|------|
| 1 | 是否接受网页读取的平台风控风险 | 不接受则访客/加购等数据回到每日人工导出 |
| 2 | 是否订阅一款拼多多市场数据工具 | 不订阅则需读拼多多前台，风险更高 |
| 3 | 选用哪款铺货代发工具 | 上架与自动下单的覆盖程度 |
| 4 | 首批 1–2 个类目 | 选品数据与规则的起点 |
| 5 | 是否准备单独的 1688 采集账号 | 风控隔离 |
