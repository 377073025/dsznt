## 1. 设计总览

### 1.1 产品形态

| 部分 | 形态 | 说明 |
|------|------|------|
| 后端 | 本地常驻服务 | 一组智能体 + 数据层 + 调度 + 流程引擎，按天/按周自动运转 |
| **主入口** | **飞书机器人** | 早报、选品推荐、拍板、写入确认、异常提醒、对话修改，全部在飞书完成 |
| 辅助入口 | Web 控制台（局域网） | 闭环总览、数据中心、任务看板、规则配置，主要给店主使用 |
| 外部工具 | 第三方铺货代发工具、市场数据工具、生图服务 | 作为数据源和执行工具接入，不重复开发 |

### 1.2 设计原则 → 设计手段

| 原则 | 设计手段 |
|------|----------|
| **人工尽量少（基准）** | 每个环节按「自动 → 半自动 → 人工兜底」设计，系统自动降级并在飞书说明当前级别 |
| 先接数据，再谈 AI | 独立数据层；缺数据硬性阻断分析；数字由程序算，LLM 只解读 |
| 分析只读 | 分析类、选品类智能体只注册只读工具 |
| 店主只跟 CEO 说话 | 所有建议、选品推荐、确认请求经 CEO 汇总后统一从飞书发出 |
| 人来拍板 + 二次确认 | 状态机中「已批准」「写入确认」两道闸门只能由有权限的飞书用户触发 |
| 验收才算完 | 派活时生成验收清单；验收不过回到执行 |
| 结果回流 | 执行完成自动登记改动事件；到期复盘；测款结果反哺选品权重 |
| 成本可控 | 程序先汇总再给 LLM；限制轮数；模型分级；缓存与 Batch；不用截图读数 |

### 2.1 技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| 后端 | Python 3.12 + FastAPI | 数据处理生态好 |
| LLM | Anthropic Python SDK（Messages API + tool use） | 日常任务直接调 API，不用全能编程 Agent 框架 |
| 模型 | Opus 5.5：CEO 汇总、验收<br>Sonnet 5.5：运营分析、选品需求侦察、合规审查、推荐撰写、文案、AI 认路<br>Haiku 5.5：同款初筛、违禁词初筛、格式整理 | 按任务难度分级 |

| 调度 | APScheduler | 每日、每周、到期复盘 |
| 数据库 | SQLite（MVP）→ PostgreSQL | 单机起步 |
| 计算 | pandas | 所有数字在程序里算 |
| 飞书 | 飞书开放平台官方 Python SDK，长连接模式 | 本地部署不需要公网 IP（卡片回调待 POC 验证，失败时用内网穿透） |
| 前端 | React + Vite + Tailwind + ECharts | 深色驾驶舱风格 |
| 生图 | 适配层，可插拔多家服务 | 修图、换背景、场景合成 |

## 3. 数据层设计

### 3.1 三通道与自动降级

```
请求某数据项 → 查该数据项的通道优先级表
   ├─ 通道1 API 可用？ ── 是 → 获取 → 校验通过 → 入库
   │                     └ 否/失败
   ├─ 通道2 网页读取 ── 固定脚本成功 → 入库
   │                   ├ 脚本失败 → AI 认路修复 → 成功 → 更新脚本 → 入库
   │                   └ 遇到验证码/登录失效 → 飞书通知人工处理 → 处理后续跑
   └─ 通道3 人工导入 ── 飞书通知「请导出 xx 并发给我」+ 图文指引 → 收到文件 → 解析入库 → 自动补跑下游任务
超过时限仍无数据 → 标记「数据缺失」，下游不分析、不估算
```

### 3.2 数据项与通道优先级

| 数据项 | 通道优先级 | 频率 |
|--------|------------|------|
| 本店商品（标题、主图、价格、SKU） | API → 网页 → 人工 | 每日（同时生成快照） |
| 本店订单统计 | API → 网页 → 人工 | 每日 |
| **本店单款访客、加购、下单** | 网页 → 人工 | 每日 |
| 推广数据 | 网页 → 人工 | 每日 |
| 拼多多关键词热度、竞争度 | 网页 → 人工 | 每周（选品前） |
| 类目热销榜、竞品销量价格 | 市场数据工具（网页/导出）→ 拼多多前台（网页，限量） | 每周 |
| 1688 以图搜货 / 关键词搜索 | 1688 API → 网页 | 每周（分批） |
| 1688 商品详情与供应商指标 | 1688 API → 网页 | 每周；在售款货源每日检查价格库存 |
| 代发自动下单标记 | 铺货代发工具（网页/导出） | 每周 |
| 改动事件 | 系统执行时自记 + 每日商品快照对比 + 人工补登 | 实时 / 每日 |

### 3.3 网页读取层

| 组件 | 职责 |
|------|------|
| 浏览器会话管理 | 每个平台一个独立的持久化浏览器配置；拼多多后台用店铺主账号，1688 用**独立采集账号** |
| 固定脚本库 | 每个页面任务一个脚本（打开 → 定位 → 读文本/点导出 → 返回结构化数据），带版本号 |
| AI 认路 | 脚本失败时，Sonnet 5.5 读取页面无障碍树/文本结构（不是截图）定位目标元素，完成任务后生成新版脚本；单次最多 15 步 |
| 看图 | 只在同款判断、合规审查、上架核对时截取图片区域，交给多模态模型 |
| 限速器 | 按平台限频：拼多多后台每次任务间隔 ≥ 30 秒；1688 页面间隔 1–3 分钟、每日上限可配（默认 60 页）；拼多多前台每日上限默认 20 页 |
| 风控熔断 | 出现滑块/验证码 → 暂停该平台并通知人工；出现「账号异常」「访问受限」→ **熔断该平台 24 小时以上**，需店主在飞书确认后才恢复 |
| 会话保活 | 检测登录失效 → 飞书推送扫码登录提醒 |

**只读约束**：网页读取层只允许打开页面、读取、点击导出/搜索/翻页类元素；脚本中出现提交、保存、发布、删除类操作会被拒绝执行。

### 3.4 数据校验

- **完整性**：每个数据项定义必需字段，缺失则标记，不进入分析
- **数字一致性**：LLM 输出中的每个数字必须能在输入数据中找到，否则重试一次，仍不符则丢弃该条输出并记录
- **合理性**：转化率 > 100%、价格为 0 等异常值拦截

## 4. 智能体设计

### 4.1 角色总表

| 智能体 | 子角色 | 模型 | 权限 | 输入 → 输出 |
|--------|--------|------|------|-------------|
| **选品智能体** | 需求侦察 | Sonnet 5.5 | 只读 | 店内好卖款、热词、榜单 → 需求清单 |
| | 货源匹配 | 程序 | 只读 | 需求清单 → 1688 候选货源 |
| | 同款审查 | Haiku 5.5（不确定时升级 Sonnet） | 只读 | 竞品图 + 货源图 + 规格 → 是否同款、置信度 |
| | 合规审查 | 规则 + Sonnet 5.5 | 只读 | 货源图文 → 侵权、资质、图文一致、违禁词 |
| | 推荐撰写 | Sonnet 5.5 | 只读 | 打分结果 → 推荐理由与风险提示 |
| | 测款跟踪 | 程序 + Sonnet 5.5 | 只读 | 新品 14 天数据 → 留/改/汰建议 |
| **运营 Agent** | 看数诊断 | Sonnet 5.5 | 只读 | 漏斗、分款、改动事件 → 诊断结论 |
| | 给建议 | Sonnet 5.5 | 只读 | 诊断 → 「建议……，因为……」 |
| | 复盘解读 | Sonnet 5.5 | 只读 | 改动前后指标 → 效果结论 |
| **CEO Agent** | 汇总 / 派活 / 验收 / 对话 | Opus 5.5 | 读全部、写任务表，不直接写店铺 | 各智能体输出、拍板结果、执行产物 → 早报、周选品报告、任务单、验收结论 |
| **执行 Agent** | 文案 | Sonnet 5.5（违禁词初筛 Haiku） | 只产出文本 | 已批准任务 → 标题、卖点、详情 |
| | 图片 | Sonnet 5.5 编排 + 生图服务 | 调用生图、读写素材库 | 已批准任务 → 修图、换背景、场景图、从素材库选图 |
| | 上架物料 | 程序 | 写产物区 | 图文产物 → 上架物料包 / 推送到铺货工具 |

### 4.2 选品智能体

**每周流程**（默认周一 06:00 开始，数据采集分摊到前一周每天进行）：

```
需求侦察 ──→ 货源匹配 ──→ 硬性过滤 ──→ 同款审查 ──→ 合规审查 ──→ 利润与打分 ──→ 推荐撰写 ──→ CEO 周报
 50–100 个     500–1000 个     100–200 个     60–100 个     30–60 个        Top 5–10       ≤ 5 款推荐
```

**三种触发**

| 触发 | 条件 | 种子 |
|------|------|------|
| 延伸选品 | 某款连续 2 周位列店内前 3，或回头客占比高 | 该款主图、同供应商其他款、同系列关键词 |
| 补位选品（V0.2） | 在售款衰退、货源涨价/断货 | 该款主图 → 以图搜替代货源 |
| 机会选品 | 每周定时 | 关键词飙升词、类目榜单上升款 |

**规则来源**：硬性过滤 10 条、打分 7 维度、利润公式、测款规则均在 `rules/` 中以配置实现，参数在 Web「规则配置」页可调（见 04 号文档 3.4–3.5 节）。

**同款审查输出**

```json
{
  "demand_id": "d_031",
  "offer_id": "1688_6543210",
  "same_product": true,
  "confidence": 0.92,
  "evidence": ["杯身纹理一致", "盖子形状一致", "规格 200g 与竞品一致"],
  "concerns": ["货源图无品牌标识，竞品图有贴标，需确认是否为白牌"]
}
```

### 4.3 运营 Agent

- 输入：程序算好的整店漏斗、分款指标、对比基准、异常标记、改动事件
- **样本门槛**：单款周访客 < 200 时不判断转化率异常；日报只报大盘，分款诊断默认按周
- 每条建议：「建议……，因为……」+ 证据（数据与改动事件）+ 置信度
- 无匹配改动事件时只写现象，置信度标低，不编造原因

### 4.4 CEO Agent

| 职责 | 触发 | 行为 |
|------|------|------|
| 日报汇总 | 每日 07:40 | 合并运营建议、复盘结论、数据异常 → 飞书早报 |
| 周选品汇总 | 每周一 | 合并选品推荐（≤ 5 款）+ 测款进展 → 飞书选品周报 |
| 派活 | 拍板「同意」后 | 拆任务、指定执行 Agent、生成验收清单、标注是否需写入确认 |
| 验收 | 执行完成后 | 对照清单检查物料（看图、查文本）；需要店铺实际状态时调用网页读取核对 |
| 对话 | 用户在飞书发消息 | 回答问题；下达的指令转成建议/任务，走同样的审批流程 |

### 4.5 执行 Agent

| 能力 | 做法 | 约束 |
|------|------|------|
| 文案 | 标题、卖点、详情；内置拼多多标题规则 | 违禁词、极限词、品牌词校验 |
| 图片 | 素材库挑选 → 修图/换背景/加卖点/场景合成 → 存入素材库新版本 | **不生成商品本体**；保留原图与每个历史版本 |
| 上架物料 | 打包：标题、主图 5 张、详情图、SKU 表、价格、货源链接 | 有开放平台资质时走 API；否则推送到铺货工具或供人工上传 |

所有执行 Agent 启动时校验任务状态必须为 `approved`，涉及写店铺的步骤必须经过 `write_confirm`。

### 4.6 智能体工作台：单独运行、状态可见、单独任务

**核心思路**：把每个智能体的每项能力做成一个可以独立调用的「能力」（输入 → 输出，自带工具和校验）。主流程和单独任务**调用的是同一个能力**，区别只在于由谁发起、跑在哪个通道、结果交给谁。

```
                 ┌──────── 主流程（定时 / 事件）────────┐
                 │ 每日采集 → 运营分析 → CEO 早报 ……    │──→ 主通道（优先）──┐
                 └──────────────────────────────────────┘                   │
                                                                             ├─→ 能力（同一份代码）──→ 运行记录
                 ┌──────── 单独任务（人工提交）──────────┐                   │       │
                 │ Web 工作台 / 飞书指令                  │──→ 单独通道 ──────┘       ├─ 主流程：结果进早报 / 建议 / 任务
                 └──────────────────────────────────────┘                           └─ 单独任务：结果只进该任务；可「转为建议 / 转为任务」
```

**可单独调用的能力**

| 智能体 | 能力 | 人工输入 | 网页读取 | 产出 |
|--------|------|----------|:---:|------|
| 选品 | 需求侦察 | 关键词或类目 | 可能 | 需求清单（热度、趋势、竞品） |
| 选品 | 找货源 | 拼多多商品链接或图片 | ✅ | 1688 候选货源 + 同款与合规结论 |
| 选品 | 单品评估 | 1688 链接（可选目标售价） | ✅ | 硬性过滤结论、单款净利、打分明细、风险 |
| 选品 | 测款评估 | 在售商品 | — | 当前留 / 改 / 汰判断 |
| 运营 | 诊断 | 商品（或整店）+ 时间段 | — | 诊断结论 + 建议草稿 |
| 运营 | 复盘 | 改动事件 | — | 改动前后对比结论 |
| CEO | 问答 / 汇总 | 自然语言问题 | — | 回答（只读，不派活） |
| 执行 · 文案 | 写文案 | 商品 + 要求 | — | 标题、卖点、详情草稿 |
| 执行 · 图片 | 修图 | 商品 + 素材 + 要求 | — | 素材库新版本（草稿） |
| 执行 · 上架物料 | 打包 | 候选或商品 | — | 上架物料包 |

**智能体状态**

| 状态 | 含义 | 展示内容 |
|------|------|----------|
| 空闲 | 没有排队和运行中的任务 | 上次运行时间与结果 |
| 排队中 | 有任务在等执行 | 排队数量、最早的任务 |
| 运行中 | 正在执行 | 来源（如「主流程 · 每日运营分析」或「单独任务 #12」）、当前步骤（如「调用工具 get_metrics」「等待模型」「数字校验重试」）、已用轮数 / token / 费用、已运行时长 |
| 等待人工 | 卡在人工环节 | 等什么（写入确认、验证码、登录）及等待时长 |
| 已暂停 | 预算用完、平台熔断、能力未接入 | 原因与恢复条件 |

**不影响主流程的四道隔离**

| 隔离 | 做法 |
|------|------|
| 执行通道 | 主流程与单独任务分两个通道各自执行；单独任务同一时间最多 1 个，主流程任务从不排在单独任务后面 |
| 预算 | 单独任务有独立的每日预算（默认 ¥2，可配）；用完后单独任务排到次日，主流程不受影响 |
| 网页读取 | 与主流程共用每个平台的浏览器（同一时刻只有一个任务使用）；单独任务每天最多用掉页数上限的 20%；主流程采集时段（默认 06:00–08:30）内单独任务不发起网页读取，自动顺延 |
| 结果 | 单独任务的产出不进早报、不生成建议、不触发派活；只有人工「转为建议 / 转为任务」后才进入主流程的拍板和写入确认 |

**单独任务状态**

```
submitted → queued → running ─┬ done ─┬（转为建议）→ promoted
                              │       └（转为任务）→ promoted
                              ├ failed
                              └ cancelled（排队中或运行中均可取消）
queued ─（预算 / 页数额度用完）→ deferred → 次日 queued
```

## 5. 流程与状态机

### 5.1 运营建议（Suggestion）

```
generated ─(CEO汇总)→ reported ─┬ 同意 ─→ approved ─(派活)→ dispatched ─(验收通过)→ done ─(观察期到)→ reviewed
                                ├ 改一改 → revising ─(CEO改写)→ reported
                                └ 不同意 → rejected
```

### 5.2 选品候选（Candidate）

```
discovered ─(硬性过滤)→ filtered ─(同款/合规)→ verified ─(打分)→ scored ─(进入周报)→ recommended
recommended ─┬ 同意上新 → approved ─(派活：文案/图片/物料)→ preparing ─(铺货完成并验收)→ listed
             ├ 改一改   → revising → recommended
             └ 不要     → rejected（记录原因，用于调权重）
listed ─(14天)→ testing ─┬ keep（留款）
                         ├ optimize（交运营 Agent 优化，再观察 7 天）
                         └ drop（建议下架 → 店主确认 → delisted）
```

### 5.3 任务（Task）

```
pending → running → produced ─┬(需写入)→ awaiting_write_confirm ─确认→ writing → submitted
                              └(不需写入)──────────────────────────────────→ submitted
submitted ─(CEO验收)┬ 通过 → accepted
                    └ 不通过 → rework（≤ 2 次，超过 → escalated 报店主）
```

### 5.4 数据采集任务（Fetch Job）

```
scheduled → running ─┬ success
                     ├ script_failed → ai_repairing ─┬ success（脚本更新）
                     │                               └ failed → manual_requested
                     ├ captcha / login_expired → waiting_human → running
                     ├ risk_blocked → circuit_open（熔断，待店主确认恢复）
                     └ manual_requested ─(收到导入文件)→ success
```

### 5.5 时间表

| 时间 | 动作 |
|------|------|
| 每日 06:30 | 采集本店数据（商品快照、访客加购、订单、推广） |
| 每日 07:00 | 指标计算、快照对比生成改动事件、异常标记 |
| 每日 07:15 | 运营 Agent 分析；测款跟踪检查 |
| 每日 07:40 | CEO 汇总 → 08:00 飞书早报 |
| 每日分时段 | 选品数据分批采集（1688 以图搜货、详情；限速） |
| 每周一 06:00 | 选品流程汇总计算 → 08:30 飞书选品周报 |
| 拍板后 | 派活 → 执行 → 写入确认 → 验收 |
| 每月 1 日 | 选品权重调优建议（需店主确认） |

时间均可在设置中修改。

## 7. 交互设计

### 7.1 飞书（主入口）

| 卡片 | 时机 | 内容 | 按钮（权限） |
|------|------|------|--------------|
| 店铺早报 | 每日 08:00 | 大盘漏斗、最好卖 / 正常 / 掉在哪、建议（≤ 5 条）、复盘结论、数据状态 | 每条建议：同意 / 不同意 / 改一改（店主） |
| 选品周报 | 每周一 | ≤ 5 款推荐：图、售价/成本/毛利、供应商、代发自动化、理由、风险；测款进展 | 同意上新 / 不要 / 改一改（店主） |
| 写入确认 | 执行到写入前 | 改前 / 改后对比 | 确认 / 取消（店主） |
| 铺货待办 | 无 API 资质时 | 物料包链接、铺货工具操作指引 | 已铺货（店主、运营） |
| 测款结论 | 测款期满 | 14 天数据、留/改/汰建议 | 同意 / 不同意（店主） |
| 需要人工 | 采集失败、验证码、登录失效、熔断 | 原因、操作指引 | 已处理 / 恢复采集（店主；恢复熔断仅店主） |
| 月度调权 | 每月 | 各维度与测款成功的关系、建议的权重调整 | 同意 / 不同意（店主） |

**「改一改」**：点击后在卡片下回复自然语言，CEO 改写后发新卡片；同一条最多 3 轮，超过则提供可编辑文本框。

**卡片回调**：3 秒内返回确认，耗时处理完成后调用「延时更新卡片」接口刷新为最新状态。

### 7.2 Web 控制台（辅助，局域网）

| 任务看板 | 待执行 → 执行中 → 待写入确认 → 待验收 → 完成 / 返工 |

## 8. 权限与安全

### 8.1 角色

| 动作 | owner（店主） | operator（运营） | viewer |
|------|:---:|:---:|:---:|
| 查看报告、看板 | ✅ | ✅ | ✅ |
| 拍板建议 / 同意上新 / 测款结论 | ✅ | ❌ | ❌ |
| 写入确认 | ✅ | ❌ | ❌ |
| 标记已铺货、上传数据、处理验证码 | ✅ | ✅ | ❌ |
| 查看智能体状态与运行记录 | ✅ | ✅ | ✅ |
| 提交 / 取消单独任务、转为建议 / 转为任务 | ✅ | ✅ | ❌ |
| 调整单独任务预算与页数额度 | ✅ | ❌ | ❌ |
| 恢复熔断、修改规则、管理用户 | ✅ | ❌ | ❌ |

### 8.2 安全措施

| 层面 | 措施 |
|------|------|
| 工具隔离 | 分析、选品类智能体只注册只读工具；写工具内部再次校验审批状态 |
| 人工闸门 | `approved`、`write_confirm`、熔断恢复只能由 owner 通过飞书或 Web 触发，智能体无法置位 |
| 网页只读 | 网页读取层拒绝提交、保存、发布、删除类操作 |
| 账号隔离 | 1688 采集账号与采购付款账号分离 |
| 风控熔断 | 风险提示即停，需人确认恢复 |
| 草稿优先 | 商品类写操作默认草稿或物料包 |
| 回滚 | 写操作保存 before 快照；素材库保留历史版本 |
| 凭证 | API 凭证、浏览器会话加密存储；日志脱敏 |
| 数据外发 | 只把汇总后的数据和必要图片发给模型 API |
| 审计 | 所有写操作、状态变更、权限操作记入审计日志 |

## 9. 成本控制设计

| 措施 | 实现 |
|------|------|
| 程序先汇总 | 给 LLM 的只是汇总后的几十行数据，不给原始报表 |
| 模型分级 | Haiku 初筛 → Sonnet 主力 → Opus 只做汇总与验收 |
| 提示词缓存 | 系统提示词、工具定义、规则说明固定在前，加缓存标记 |
| Batch | 每日运营分析、每周同款/合规审查走 Batch 接口（五折） |
| 轮数上限 | 每个智能体单次任务最多 6 轮工具调用；AI 认路最多 15 步 |
| Token 预算 | 使用 task budget 限制单次任务总量；`llm_usage` 实时累计，超日预算告警并降级 |
| 不截图读数 | 网页取数读文本，截图只用于看图类任务，且只截图片区域 |
| 对话轮数 | 「改一改」最多 3 轮 |

**预算基线（单店/月）**：LLM ¥70–130（含选品）；生图 ¥30–150；网页修路 ¥0–20。超过基线 150% 时飞书告警。
