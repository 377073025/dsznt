## 第 1 天：搭环境 + 拼多多后台关键词分析（A1）

| 项目 | 内容 |
|------|------|
| **目标** | 确认能自动读到拼多多后台的关键词数据，并开始连续 5 天的稳定性测试 |
| **我来做** | ① 搭 POC 环境（Python、浏览器自动化）② 在独立浏览器中打开拼多多商家后台 ③ AI 认路找到「数据中心 → 关键词分析」④ 读取你的 10 个关键词的搜索热度、竞争度、趋势 ⑤ 把这条路线保存为固定脚本 ⑥ 设置每天定时运行 |
| **你来做** | 扫码登录拼多多商家后台（一次）；确认读到的数字与你在后台亲眼看到的一致（抽查 3 个） |
| **产出** | `poc/output/A1_关键词_第1天.csv`；后台页面结构说明；登录会话有效期记录 |
| **记录** | 是否遇到验证；脚本耗时；是否支持导出 |
| **通过标准** | 当天成功读取 10 个关键词的数据，数字与后台一致 |

## 第 2 天：1688 以图搜货（A3）

| 项目 | 内容 |
|------|------|
| **目标** | 确认能用竞品主图在 1688 搜到同款货源，且不被风控拦住 |
| **我来做** | ① 用独立浏览器登录 1688 采集账号 ② 逐张上传 20 张竞品主图做以图搜货，每张间隔 1–3 分钟，分两批（上午 10 张、下午 10 张）③ 每张图读取搜索结果前 10 个货源的标题、价格、链接、主图 ④ 记录每次是否出现滑块/验证码 |
| **你来做** | 扫码登录 1688 采集账号；出现验证码时手动完成（飞书或屏幕提醒）；浏览结果，粗看每张图的前 10 个里有没有真正的同款 |
| **产出** | `poc/output/A3_以图搜货.csv`（20 × 10 条）；风控事件记录 |
| **通过标准** | ≥ 15 张图能在前 10 个结果里找到同款；验证码 ≤ 1 次 |
| **不通过时** | 验证码频繁 → 降速重试一次；仍频繁 → 记录为高风险，改为依赖 1688 开放平台接口或铺货工具的货源池 |

## 第 3 天：1688 详情页字段（A4）

| 项目 | 内容 |
|------|------|
| **目标** | 确认硬性过滤和利润计算需要的字段，在 1688 页面上能读到哪些 |
| **我来做** | 从第 2 天结果中选 30 个货源，逐个打开详情页和店铺页（间隔 1–2 分钟），读取下表字段，统计每个字段的可得率 |
| **你来做** | 必要时处理验证码；对照 3 个商品页确认读取正确 |
| **产出** | `poc/output/A4_详情字段.csv`；字段可得率表 |
| **通过标准** | 「必需字段」可得率 ≥ 90% |

要读取的字段：

| 字段 | 级别 | 用途 |
|------|------|------|
| 代发价 / 批发价、SKU 规格与价格 | 必需 | 利润计算 |
| 是否支持一件代发 | 必需 | 硬性过滤 H1 |
| 运费 / 发货地 | 必需 | 利润计算 |
| 库存 | 必需 | 硬性过滤 H10 |
| 商品主图、详情图 | 必需 | 同款审查、素材 |
| 店铺经营年限 / 诚信通年限 | 重要 | 硬性过滤 H9 |
| 发货/揽收时效指标 | 重要 | 硬性过滤 H4 |
| 回头率 | 重要 | 供应商评分 |
| 品质退货率 / 纠纷率 | 重要 | 硬性过滤 H5 |
| 近 30 天成交量 | 重要 | 需求参考 |
| 是否支持代发推单 / 代发工具标记 | 加分 | 代发自动化评分 |

## 第 4 天：AI 同款判断准确率（A5）

| 项目 | 内容 |
|------|------|
| **目标** | 确认 AI 看图判断「是不是同一个货」够准、够便宜 |
| **我来做** | ① 用 Haiku 5.5 对 50 对标注图片逐对判断是否同款，并给出置信度 ② 与你的标注对比，算准确率 ③ 对判错的对子分析原因 ④ 准确率不够时，改用 Sonnet 5.5 或加入规格/重量对比再测一次 ⑤ 记录实际 token 和费用 |
| **你来做** | 确认第 0 天的 50 对标注已完成；看判错的案例，确认是 AI 错了还是标注有分歧 |
| **产出** | `poc/output/A5_同款判断结果.csv`；准确率、误判类型、单对费用 |
| **通过标准** | 准确率 ≥ 90%，且「把不同款判成同款」的错误 ≤ 2 对（这类错误会导致售后问题，比漏判更严重） |

## 第 5 天：市场数据工具 + 1688 开放平台（A2、A6）

| 项目 | 内容 |
|------|------|
| **目标** | 确认需求端数据来源；确认 1688 接口能否作为主通道 |
| **我来做（A2）** | 在市场数据工具试用账号中读取所选类目 Top 100 热销商品（名称、价格、销量、主图）和关键词趋势；评估是否支持导出、数据更新频率 |
| **我来做（A6）** | 根据你反馈的开放平台申请结果，如已获批，用接口跑一次关键词搜索和图片搜索，与第 2 天的网页结果对比 |
| **你来做** | 登录市场数据工具试用账号；查看 1688 开放平台申请状态并告诉我结果；询问工具正式价格 |
| **产出** | `poc/output/A2_类目榜单.csv`；工具评估（数据量、精度、能否导出、价格）；A6 结论 |
| **通过标准** | A2：能拿到所选类目 Top 100；A6：明确「能/不能/审核中」 |

同一天检查 **A1 已连续运行 5 天**的结果。

## 第 6 天：小规模全流程串跑

| 项目 | 内容 |
|------|------|
| **目标** | 把前几天的环节串起来，看完整链路是否通顺，并实测耗时和费用 |

## 风控事件记录要求（全程）

每次出现以下情况都要记录（我会自动记，你手动处理时也请告诉我）：

| 记录项 | 例子 |
|--------|------|
| 时间、平台、页面 | 2026-10-27 10:32，1688，以图搜货结果页 |
| 事件类型 | 滑块 / 短信验证 / 强制重新登录 / 访问受限提示 |
| 当时的访问频率 | 过去 1 小时访问 12 个页面 |
| 处理方式 | 人工完成滑块后继续 / 暂停至次日 |

**出现「账号异常」「访问受限」类提示时，立即停止该平台的所有自动访问**，等评估后再继续。
